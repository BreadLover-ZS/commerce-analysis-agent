## 目标与非目标

面向 Agent / AI 应用工程师求职，补齐“事实可核对、研究发现可传递、效果可比较”的闭环。
沿用 FastAPI、SQLAlchemy、LangGraph、Deep Agents、既有租约与权限体系。
不新增自由 SQL、自动业务写操作、无约束公开查询、MCP/A2A 或自动长期记忆。
不在缺少真实凭据时声称模型质量或多 Agent 收益；不改 Git 远端、不提交或推送。

## 实施顺序与接口

### M1：事实绑定（P0）

经营工具返回 `fact_catalog`，每个指标包含实体ID/名称、指标、数值、单位、起止周期和
可选库存快照日期。MetricReference增加相同维度。校验核对整个事实元组；不接受缺少
目录或错配维度的旧引用。带经营指标的事实句由程序渲染，模型负责选择事实和组织分析。
直接调用校验器时，自由改写的指标句不能通过；live草稿先验证引用，再生成权威事实句。
分析与建议的语义仍需模型/人工核验，不能把这项修复描述为全面消除幻觉。

验收：商品互换、指标/单位/周期/快照错配、数值改动、未知引用均拒绝；正常样例及
带数字商品名通过；金额不表示净利润；长请求与计划字段长度一致。

### M2：库存复盘与数据完整性（P1）

销售与库存读取商品/日记录，显式区分零记录、部分日期、完整记录。每日零销量需要
显式零行；缺失不能补零。显示期望/观察记录、缺失天数；库存覆盖仅在日期完整时提供，
不完整时保留观测销量并注明无法估计。记录快照相对周期的距离与过期提示。
库存在数据库中按缺数、缺货、积压、正常的优先级与严重程度排序后取100个；返回总数、
展示数、截断标记。风险是历史估计，不改成未来预测。销售补充上一个同长度周期比较，
前期缺数或基数非正时不计算增长率。仍不承诺跨工具共享一致性快照。

验收：部分日期不产生虚假完整覆盖；第101个高风险商品仍被优先返回；缺数/零销量与
快照过期区分；前期无数据/零基数不计算百分比。

### M3：证据选择与研究发现（P1）

内部词法检索覆盖整个授权小语料，超过显式容量则拒绝并提示，不悄悄只搜前2000片段。
证据包按指标优先、文本来源分配、相关性排序和窗口提取组织；记录选择ID、遗漏数、
截断与字符预算。原始证据账本保留完整片段，包内窗口不能冒充完整原文。

增加 ResearchSynthesis（发现、冲突、缺口）；每项发现必须提供 evidence_id 与逐字
支持片段。程序拒绝未知ID、伪造摘录及单来源“冲突”。通过图State持久化并交给draft，
随产物导出 research.json。摘录匹配只证明来源存在，推理关系仍需人工复核。

验收：晚到的不同来源进入包、授权不变；未知ID/伪造摘录被拒；图恢复保留研究结果；
脚本模型协议证明draft实际收到发现；不保存模型隐藏思考过程。

### M4：三种策略与质量评估（P1）

增加 workflow 策略：直接使用允许关键词搜集资料，再结构化归纳；single/multi保留
Deep Agents工具选择。三者使用相同业务数据、报告与校验，公开查询仍仅允许原样关键词。
固定评估扩展到至少30条，区分确定性契约、SDK协议、真实模型质量和人工评分。
导出脱敏待标注表，支持正确性/证据支持/完整性/工具行为评分、结论说明和失败原因。
比较器要求数据集与配置指纹一致，至少3轮；展示回退率、用量完整性、P50/P95、费用和
实际委派次数；没有人工标签时不给质量结论。外部来源未冻结时显式说明比较局限。

验收：错误商品句/净利润误称/遗漏要求不得被模板契约掩盖；对比不能混入demo模拟委派；
缺少标签、轮次、不同数据集时不能宣称质量收益。真实模型未配置时标记未验。

### M5：交付与运维（P1）

更新界面三种策略及研究结果入口、中文调用链与学习说明。提供停止本地服务后创建
SQLite运行目录备份、在空目录恢复并校验的脚本与测试。PostgreSQL/容器/HTTPS的
现有烟测与部署入口继续保留，未能执行的项独立标记。备份包含敏感运行数据，不上传Git。
