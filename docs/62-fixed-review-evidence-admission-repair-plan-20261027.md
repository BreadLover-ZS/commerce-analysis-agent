# 固定复核上下文与付费准入修复方案（2026-10-27）

依据 [61 号真实失败](61-boundary-v2-U-formal-stop-and-root-cause-20261027.md)，目标是在再次付费前证明：复核的每项结论都有实际发送的授权证据，大小不足时请求数为零，模型自评不能替代这一检查。当前方案尚未实施；失败轮保持停止，不增加额度、不重写原始判定，G7 排除。

## R1：冻结新的上下文子契约

为新固定 Task 冻结 `model_evidence_context_version=2`，缺省字段的旧 Task 继续 v1。服务端设置、幂等重试、Worker 恢复和检查点均按冻结字段选择实现；不能用当前设置重解释历史任务。保留旧上下文模块，新增固定复核专用版本实现。answer-contract-v5、边界策略 2 与计量协议 2 的职责保持清楚，新源码／上下文策略进入正式冻结材料。

验收：版本 1 与 2 对同一大型开发输入可明确表现旧缺陷与新行为；切换部署设置后旧 Task／幂等返回仍使用原上下文契约。旧 267 份历史评分、本轮五份原判定与原始调用记录字节不变。

## R2：紧凑投影与完整权威引用

从持久化授权证据构造复核投影，保留 source id／content hash、bundle／dataset 绑定、实体范围、币种单位、准确周期、适用性／缺行口径以及最终报告引用的事实键值。事实来自证据账本，不能从报告自身反向生成“证据”。规则／文字依据保留原文定位和窗口，建议前提保留对应原始事实，不能只给一份程序“已验证”的结论。

去除 metrics 与 fact_catalog 的重复表示、无关完整执行清单和完成度自证字段；用实际报告引用和候选建议前提选择必要信息，不能仅凭长度截断最前若干条事实。前期值、差额、贡献尾项、适用性、必要规则都须保留。报告与证据的引用图必须逐项可解析，并记录保留／排除与原因。

验收：已执行 H01 的 28,659 字符反例在原 28,000 上限内保留完整必要权威引用；单独检查两期支付／退款／净额、贡献、分母、建议前提与不适用边界。增加无关事实不能挤掉必答引用；伪造来源 hash、缺事实键、错单位／周期／实体均拒绝。超大必要内容放不下时不得静默丢失来源。

## R3：付费前强制门禁

固定流程第一条付费请求前，从确定性报告与可选建议的已知事实前提检查必要证据是否可装入上下文；可提前发现的容量失败须零模型发送。形成最终草稿后，在语义复核发送前再次逐项核查所有引用、证据绑定和容量，防止草稿变化引入未覆盖项。

空来源、缺引用、超预算、来源绑定变化均停止。使用现有发送计量协议记录真实 NOT_SENT 与零发送证明，不误记成免费 UNKNOWN，不重试、不自动切换模型，不把固定两次 HTTP 上限提高来纠错。拒绝原因独立保存，不能被有效的确定性兜底报告掩盖。

验收：真实 SDK MockTransport 断言完整请求消息；必要上下文不够时 transport 触发次数为 0，费用 journal、Task 计量与 NOT_SENT 证明一致，旧 UNKNOWN 冻结仍计入硬上限。中断后恢复已保存响应不补发，过期 lease 和来源变更不能复用旧许可。

## R4：评分、审查与反例独立

新增与版本绑定的 `semantic_context_coverage` 准入断言，独立读取保存的实际 HTTP 请求和最终报告，对照原始授权证据，不直接相信生产选择 manifest 或模型返回的 PASS。固定流程数值正确、模型复核有效、人工内容审查分开计分；任何一项不合格都阻断下一位。

本地 Mock 不能无条件返回 `unsupported_claim_ids=[]`：先断言实际请求含全部必要证据，再返回结构化结果。加入“空上下文＋乐观模型 PASS”“空上下文＋合理拒绝”“仅差一个引用”“边界值 27,999／28,000／28,001”“重复事实／长 SKU／大完成清单／文档规则窗口”等独立开发反例。作者人工清单增加实际发送体检查，模型自己说证据齐全不算审查证明。
