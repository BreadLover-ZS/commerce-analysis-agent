# 本轮可靠性与模型验证

开始：2026-10-14；更新：2026-10-15（Asia/Shanghai）。用户选择继续完善故障恢复、
错误诊断、库存和内部文档验证。下列计划与已执行结果分开；本地通过不等于生产验收。

## 已复现的问题

旧Worker失去租约后，业务报告写入被 `StaleLease` 拒绝，但原始检查点Saver仍能保存
同一任务的状态。临时SQLite反例实际输出：业务写入拒绝true、旧检查点写入允许true、
新Worker已接管true。只在业务仓储执行租约校验不足以保护图状态。

## 实施计划与通过条件

1. 给检查点写入加租约保护。锁住任务行/SQLite写事务，在租约校验和检查点写入完成
   之间禁止其他Worker接管；覆盖checkpoint和pending writes，复用同一租约验证规则。
   读取仍通过现有Saver；保留稳定线程ID以支持人工复核和恢复。
2. 增加业务证据已提交但节点未完成、报告已提交但节点未完成、文件已写但尚未登记
   的SIGKILL测试。核对重领、证据去重、有效产物指针及真实允许的外部调用重放。
   覆盖旧Worker在接管后写检查点和登记产物的拒绝行为。
3. 服务错误记录HTTP状态和固定类别，不保存密钥、请求体、原始错误消息或隐藏推理。
   工具响应边读取边限制累计大小，不在完整响应已读入后才检查。
4. 真实模型仅使用教学模拟库存及仓库内教学规则文档；逐条核对指标、原文、引用与
   缺口。失败停在当前问题，不扩大到搜索、多Agent或完整32条用例。

检查点保护用于防止并发接管后的晚到状态污染，不把业务表与检查点两次提交描述为
同一事务；故障窗口仍可能重放节点和外部调用。未提出exactly-once或绝对费用封顶承诺。

## 已实施

- `LeaseFencedSaver`复用仓储租约规则，保护checkpoint与pending writes，并限制线程归属。
  PostgreSQL行锁覆盖整个检查点写入，SQLite使用写事务；每个任务复用一个租约连接。
- SIGKILL扩展到证据已提交、报告已提交、文件已写未登记三个窗口，保留原PDF导出窗口。
  验证重领、证据去重、产物哈希及研究是否重放；未知模型用量恢复后不继续调用模型。
- 服务错误保存HTTP状态与固定分类，不存原始错误消息/请求体。工具响应按解码后累计
  字节限量读取，超限关闭流；这不是对底层解码器瞬时分配或OS资源的绝对保证。
- Schema提前拒绝分析/建议携带指标引用；指标来源必须为metrics。文档原文中的数字
  仍可引用原文呈现，不能伪造为计算指标；商品/单位/周期/快照校验保持。
- 模型候选gaps不再强制追加到最终报告。语义复核检查limitations和任务来源范围；
  修正接收原草稿、错误ID/索引、具体评审理由。被拒绝的结构化草稿与评审结果保存为
  本任务事件，仅对任务所属用户开放；不保存隐藏推理或服务认证信息。
- 研究归纳仅接收文本原文，计算指标仍交给报告阶段。研究状态独立导出，评估新增
  `research_execution`；没有阶段产物、归纳失败或仅有最终报告都不能证明研究成功。
- 评估器支持`--case`和`--max-model-calls`，子集指纹绑定实际执行用例，不改预期数值。
