# 工作台失败与降级诊断

日期：2026-10-15。继续已选的可靠性/错误诊断目标，不新增付费模型请求。
上一轮后台已保存timeout_phase、elapsed_ms、研究validation，但工作台只显示
`任务失败：APITimeoutError`，执行事件也只展示message，用户看不到安全的诊断字段。

## 改动

- `TaskDiagnostics`使用已有任务详情和事件，不增加接口或数据库字段。失败时展示
  中文原因、可执行的下一步提示；任务编号/错误代码放在可展开的排查信息中。
- 只从与终态error_code匹配的最新model_error读取固定类别、已知阶段及有效耗时，
  旧事件缺少阶段时明确显示无法确认。任务总时限、调用预算、恢复次数耗尽优先于
  之前被捕获的模型错误，不把它们都显示为模型读取超时。
- 对终态且用量不完整的模型任务说明费用无法确认，重新提交是新任务且可能有新费用。
  页面不会自动重试、重新排队或发起付费生成。
- 研究validation未通过但报告已保存时，说明研究已退回原文摘录；保留报告、证据
  和信息缺口展示，不将报告结构通过误称为完整模型研究成功。
- 阶段/类别使用固定白名单，耗时要求非负有限数值；不会渲染事件data中的原始
  服务消息、响应体或任意未知字段。展开的长任务编号在移动端可以换行。

复用既有React/Ant Design和轮询数据，无新增运行依赖。检查过现有诊断代码与组件
接口，没有另一处同等展示；根因有UI源码和历史真实失败记录。接口用法参考
[Alert文档](https://ant.design/components/alert/)并通过已安装组件的TypeScript构建；
浏览器模拟参考[Playwright网络模拟](https://playwright.dev/docs/mock)，实施置信度95%。
