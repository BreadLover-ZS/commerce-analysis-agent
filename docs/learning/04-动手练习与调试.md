# 04 实践 · 从定位源码到独立修改

前置：[跨模块成果测试](03-链路与阅读成果测试.md)。本篇是给学习者的练习说明，不表示下面的新指标和新用例已经实现。练习一到四可先完成；练习五才修改业务逻辑。

## 1. 先准备一个能回退的练习环境

查看 `git status --short`，保留已有未提交工作；需要隔离练习时自己创建 `codex/learning-practice` 分支。运行[启动篇](02-模块/01-启动与项目结构.md)的临时 demo，使用示例数据，停止前下载需要的产物。

主线只使用 demo、测试夹具和协议替身。真实模型、外部搜索与部署可以在你理解费用和环境范围后单独安排，不是完成本系列的前提。

每项练习都留下：目标、独立预期、改动或调试入口、观察结果、验证范围、剩余问题。不要只留一张绿色终端截图。

## 练习一：用浏览器请求还原主链

**输入：** 九月月度经营复盘，选择 sales/inventory/documents，workflow，要求人工复核。

操作：

1. 记录建会话、建任务、查详情、查事件、审批、下载这几类请求。
2. 记录 task_id、状态迁移、事件 ID；认证字段只写名称，不保存值。
3. 下载一条指标证据，手算保温杯覆盖天数并核对事实句。
4. 刷新页面，解释为什么仍能看到任务；再驳回另一个任务，比较产物差异。

**通过标准：** 能画出 API 与 Worker 两条执行线；知道 202、waiting_review、degraded 的含义；不能把轮询写成 Token 流。

**提示：** 从 `App.submit/action`、`Repository.review` 与 `Worker.process` 查找，不先搜索全部 JSX。

## 练习二：在现有测试中调试经营工具

先运行下面这条已存在的测试：

```bash
uv run pytest -q tests/test_contracts.py::test_known_commerce_numbers_and_missing_period
```

需要单步时，用 IDE 的 pytest 调试入口运行同一测试，或从根目录执行：

```bash
uv run python -m pdb -m pytest -q tests/test_contracts.py::test_known_commerce_numbers_and_missing_period
```

在 `sales_summary`、`inventory_risks` 或函数返回附近设置断点。查看 start/end、current.coverage、units、observed、value、risk，不打印真实环境配置和密钥。异步 Worker 先用对应异步测试调试，暂不附加到多进程容器。

**交付：** 一张“数据库字段 → 聚合结果 → fact_catalog → Claim 文本”的映射表。

**通过标准：** 能预测缺一天、净销量为零、快照过旧三种输入会怎样变化，再用现有 quality 测试核对。断点命中不是业务正确的证据，独立预期和断言才是。

## 练习三：制造一个能解释的引用错误

只在个人练习测试中构造错误对象，不改生产校验规则。参考 [test_quality.py](../../tests/test_quality.py) 的 `test_metric_tuple_rejects_entity_unit_period_snapshot_and_value`。

依次单独改动一个维度：entity_id、unit、period_start、snapshot_as_of、value。另构造一个“引用正确，但事实文本写错商品”的例子，以及一个未知 evidence_id。

**交付：** 每个输入对应哪一层拒绝、issues 中的原因、如果只检查数字集合会漏掉什么。

**通过标准：** 正常对象能通过，每次只改一项便失败；错误没有通过“静默重写引用”被掩盖。最后能解释为什么这仍没验证全部语义推理。

**提示：** 先读 `metric_binding_issues`，再读 `render_bound_metrics` 和 `validate_report`。已有可参数化反例就复用思路，不用把测试改成完全照抄函数逻辑。

## 练习四：在离线协议测试中观察 Agent 和预算

```bash
uv run pytest -q tests/test_live_protocol.py::test_real_harness_and_structured_output_with_protocol_double
uv run pytest -q tests/test_live_protocol.py::test_missing_usage_stops_additional_model_requests
```

阅读 `ScriptedCommerceModel._generate`，画出至少三轮 messages/tool_calls 的关系：读 Skill、调用检索或 task、接收 ToolMessage、返回结果。指出脚本模型使用固定规则决定下一步，与真实模型的区别。

**交付：** single/multi 的工具集差别、一条 delegation 事件、一次用量未知导致后续准入被拒绝的链。

**通过标准：** 能说清是“真实 SDK + 离线协议替身”，并定位 `RuntimeModelMeter` 如何拦截内部模型请求。不要把这些事件当作模型实际研究质量或付费调用证据。

## 练习五：新增一个可复算的销售指标

**练习需求，尚未实现：** 在销售工具中新增“本周期记账退款金额占支付金额比例”，建议键名 `refund_amount_pct`，单位 percent。它与现有“退款件数比例”不同，不能相互替代，也不表示订单 cohort 退款率。

先写下验收，再动代码：

| 输入/情况 | 预期 |
| --- | --- |
| 支付金额 10000 分、退款 400 分 | 输出 `4.00`，单位 percent |
| 支付金额 0 | 不返回该指标，说明分母不可用，不抛除零异常 |
| 退款金额超过本周期支付金额 | 可以大于 100%，按记账周期解释，不擅自截断 |
| 记录不完整 | 保留已记录部分的限制，不宣称完整周期 |
| 换用户/组织 | 沿用服务端 tenant 范围 |
| 报告引用 | 绑定正确 key/value/entity/unit/period，程序渲染事实句 |

建议按以下顺序定位，不预先给完整实现：

1. `service.sales_summary`：计算、labels、fact_catalog、definitions 和分母缺口。
2. `evidence.deterministic_report`：增加可选 fact，缺键时兼容，不挤掉必要内容；检查每章最多 8 条的约束。
3. `metric_reference/render_bound_metrics/validate_report`：复用完整绑定，不放宽规则。
4. 选择性更新 live draft 提示，让模型能理解新口径；离线闭环不依赖真实生成。
5. 新增独立输入的指标测试及一条完整报告断言；再在 `cases.jsonl` 增加固定业务用例。

测试预期必须来自手算，不要在测试里调用同一个计算函数产生“预期”。先验证专项，再检查可能受影响的业务与离线评估。新增用例后基线将不再是 32 条，应记录新的 dataset_size；历史 32/32 仍保留。

**通过标准：** 正常值、零分母、超过 100%、缺数和实体绑定均有对应验证；demo 报告与 evidence.json 能回查；没有新增自由 SQL、模型权限或真实外部调用。

## 练习六：定位恢复故障，再写自己的分析

先阅读再运行：

```bash
uv run pytest -q tests/test_recovery.py -k 'empty_next or waits_for_collect_checkpoint'
uv run pytest -q tests/test_checkpoint_fencing.py
```

选一个故障窗口，把执行画成两条泳道：Worker A 与 Worker B。标出业务提交、checkpoint/pending writes、文件写入与登记的位置。说明旧 token 何时失效、恢复是否重读工具、哪些外部调用仍可能重复。

**交付：** 一页故障分析，包含“触发条件 → 当时持久化状态 → 当前修复/保护 → 测试断言 → 未覆盖边界”。

**通过标准：** 不通过删除 SIGKILL 测试、增加无限重试或把失败吞成成功来解决问题。能区分修复本地写入竞态和提供方请求幂等是不同工作。

## 2. 遇到问题时按层排查

| 现象 | 优先检查 | 暂时不要做什么 |
| --- | --- | --- |
| 网页能开，任务一直 queued | Worker 进程、数据库是否一致、领取条件 | 不先调整模型提示 |
| 401/403 | 会话到期、CSRF、Origin | 不关闭后端认证 |
| 422 | TaskRequest 字段、日期、文件解析限制 | 不直接放宽全部 Schema |
| 工具有结果但报告缺内容 | 来源包 manifest、finding、Claim 与截断 | 不只增大模型输出长度 |
| failed + runtime_budget | 总截止时间、阶段耗时、历史事件 | 不把 read timeout 当总时限 |
| degraded | limitations、研究验证、fallback 标志 | 不直接改状态为 succeeded |
| 用量未知 | 请求与回执计数、恢复路径 | 不清零计数重新放行 |
