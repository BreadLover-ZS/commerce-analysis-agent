## Part B：销售汇总读三个口径

### B1. 金额以“分”存储

`revenue_cents/refund_cents` 是整数，`money` 使用 Decimal 转成两位小数的元。避免在应用计算中用二进制浮点拼出金额误差。

```text
净销售额 = 支付金额 - 本周期记账退款金额
净销量 = 支付件数 - 本周期退款件数
退款件数比例 = 本周期退款件数 / 本周期支付件数
```

净销售额没有扣税费、广告、物流等成本，不能叫净利润。退款比例按记账周期统计，不是追踪某一批订单最终退款的 cohort 口径。

### B2. 没有记录不等于没有销量

`_sales_period` 用当前商品数乘周期天数得到预期记录数，再对照实际记录。当前假设每个商品每天应有一条记录，零销量也应显式存零行；未建模商品上架、下架生命周期。

缺记录时可以展示已记录金额，但必须说明不完整。不要因为 SQL 聚合用了 `coalesce` 就把业务缺失解释为真实零销量。

### B3. 比较期必须可比

前期取紧邻的同长度窗口。当前期与前期均完整、前期净销售额为正时，才给出变化率；否则保留无法比较的说明。模型不能补出缺失月份的同比或环比。

## Part C：库存风险读两遍

第一遍只看公式：

```text
周期日均净销量 = 周期净销量 / 周期天数
库存覆盖天数 = 快照库存 / 周期日均净销量
             = 快照库存 × 周期天数 / 周期净销量
```

九月教学样例中，保温杯库存 20、净销量 324、周期 30 天，因此覆盖约 `20 × 30 / 324 = 1.85` 天；配置提前期为 7 天，工具分类为 stockout。这是历史销量条件下的估计，不是未来一定缺货的预测，也不证明供应商实际交期。

第二遍看分支和排序：

| 条件 | 输出风险或限制 |
| --- | --- |
| 日期记录不完整 | incomplete；不估计覆盖天数 |
| 日期完整但净销量非正 | no_sales；不估计覆盖天数 |
| 覆盖天数小于配置提前期 | stockout |
| 覆盖天数大于工具阈值 60 天 | overstock |
| 其余情况 | normal |

边界使用严格小于/大于，相等不归入对应风险。60 天是工具算法参数，不可自动称为企业制度。

SQL 先按缺数、缺货、积压、正常及严重程度排序，再取 100 个商品。若先按 SKU 取前 100 个再排序，可能漏掉第 101 个严重缺货商品。输出保留总数、展示数和截断标记。

库存快照相对周期结束日期超过 14 天，或晚于周期结束，会记录不一致提示。销售与库存工具各有自己的只读事务，不保证跨工具读取同一数据库快照。

## Part D：事实目录怎样防止“数字正确，商品错误”

工具返回的 `fact_catalog` 不只是键和值，还包含：

```text
key + value + entity_id + entity_name + unit
    + period_start + period_end + snapshot_as_of
```

报告的 `MetricReference` 必须引用当前证据中的完整维度。程序核对维度和值，再用目录里的商品名和单位渲染事实句。模型可以选择该引用，但不能自由改写已经绑定的经营数字事实句。

例如把收纳包的 `180.00` 天写成保温杯的覆盖天数，即使数字出现在证据里，也应被拒绝。具体检查在后面的[证据篇](07-证据研究与报告校验.md)展开。

## Part E：内部资料检索与数据导入也是确定性边界

回到 `service.py` 的 `add_document → terms → search_documents`。上传解析先得到带位置的文本片段，入库时按 1000 字符步长取最多 1200 字符的块，保留原位置和字符范围；因此通常有 200 字符重叠。组织规则与私有附件共用表，但检索先按租户和用户/会话范围过滤。

当前本地检索使用词项、词频、文档频率和长度归一化打分，返回正分数的前 5 条。它是可解释的词法基线，不是向量检索或 reranker。先统计全部授权片段，超过 10000 就明确拒绝，不静默只搜索一部分。中文分词规则和固定小语料都有局限，读懂实现不等于证明真实语料召回充分。

RAGFlow 是可选外部适配器，入口在 `ToolGateway.documents`，按租户配置的数据集返回原始片段；外部真实联调仍待完成。不要把本地词法结果叫成已经完成了向量知识库验收。

经营 JSON 导入则走 [importer.py](../../../app/commerce/importer.py) 的 `CommerceImport/import_commerce` 和运维 CLI。Schema 检查重复 SKU、重复商品日记录及数值边界，事务内按租户/SKU upsert 商品，再写日记录。这个写入口没有暴露给模型工具；复盘 Agent 的只读职责不妨碍运维人员受控导入。
