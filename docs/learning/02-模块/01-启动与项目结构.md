# 02 模块 · 启动与项目结构

前置：[基础篇](00-Python与框架基础.md)。目标：运行一个不调用模型的隔离实例，知道每个进程和数据库文件的来源。

## Part A：先观察一次完整业务

需要 Python 3.12、uv、Node 22+、pnpm 11.25.0，版本依据[项目配置](../../../pyproject.toml)与[前端配置](../../../frontend/package.json)。依赖安装可能需要网络。

后端终端从仓库根目录执行：

```bash
uv sync --frozen --python 3.12
KNOWLEDGE_PROVIDER=local uv run python scripts/dev_backend.py --ephemeral --port 8091
```

前端另开终端，从仓库根目录执行：

```bash
cd frontend
pnpm install --frozen-lockfile
VITE_API_PROXY_TARGET=http://127.0.0.1:8091 pnpm dev --port 5191 --strictPort
```

打开 [隔离工作台](http://127.0.0.1:5191)，使用 `demo@example.com / demo-commerce-2026` 登录。这组端口与项目的浏览器测试配置一致；被占用时先检查已有进程，不要随意终止其他服务。

`--ephemeral` 在临时目录创建数据库和运行文件，强制设置 demo、本地账户和允许来源；退出启动脚本后临时数据清理。本次实验的结果需要在停止前下载。脚本还会继承部分父环境配置，并非所有变量都被清空；上面的 `KNOWLEDGE_PROVIDER=local` 显式选择本地知识库，避免现有 RAGFlow 配置让这次学习访问外部知识服务。

完成以下观察：

1. 选择“月度经营复盘”，周期保持 2026-09-01 至 2026-09-30，策略先选 workflow。
2. 勾选草稿复核，提交后记录任务 ID，观察排队、执行、待复核。
3. 打开“依据”，检查销售与库存证据；批准草稿，等待导出。
4. 下载 `report.md`、`report.json`、`evidence.json`、`research.json` 和 `report.pdf`。
5. 刷新页面，观察任务和事件如何重新加载。demo 通常终态为 degraded，先看具体限制再判断。

## Part B：启动脚本实际做了什么

| 顺序 | 源码入口 | 只看这些动作 |
| --- | --- | --- |
| 1 | [dev_backend.py](../../../scripts/dev_backend.py) 的 `main` | 临时目录、子进程环境、退出清理 |
| 2 | [cli.py](../../../app/cli.py) 的 `main` | `init` 执行迁移、初始化账户与样例 |
| 3 | [config.py](../../../app/core/config.py) 的 `Settings` | 模式、数据库、运行目录和校验 |
| 4 | [server.py](../../../app/api/server.py) 的 `create_app` | 构造 API；没有在请求里直接运行图 |
| 5 | [worker.py](../../../app/tasks/worker.py) 的 `main` | 打开检查点存储并运行 Worker |

```text
dev_backend.py
  → app.cli init：Alembic + 账户 + 演示数据
  → 子进程一：app.tasks.worker
  → 子进程二：uvicorn app.api.server:app
```

因此“网页能打开”和“任务能执行”是两个检查。前端和 API 正常但 Worker 没有工作时，任务可能持续排队；数据库迁移未完成时，`/health/ready` 会报告未就绪。`/health/live` 只表明 API 进程能响应。

## Part C：配置与数据分别放哪里

| 内容 | 入口 | 阅读重点 |
| --- | --- | --- |
| 应用配置 | `Settings` | 环境变量 / `.env`；`get_settings` 有缓存 |
| 业务表迁移 | [migrations/env.py](../../../migrations/env.py) | 使用配置中的数据库连接 |
| SQLite 业务库 | `database_url` | 用户、任务、指标、证据、产物登记 |
| SQLite 检查点 | `data_dir/checkpoints.sqlite` | 图的执行状态，独立于业务库 |
| 文件目录 | `data_dir/artifacts` 等 | 报告按任务和租约目录保存 |

普通本地启动方式见[根 README](../../../README.md)。本系列先使用临时实例，熟悉后再选择需要长期保留数据的启动方式。不要把环境变量的真实密钥或数据库密码写进学习笔记。

## 关键问题

1. `init`、API、Worker 分别做什么？缺少其中一个会出现什么现象？
2. 为什么备份只复制业务 SQLite 文件会漏掉恢复所需的内容？
3. demo 报告生成成功且模型调用为零，说明了什么？
