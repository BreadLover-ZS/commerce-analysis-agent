前置：[后端主链](02-后端主链.md)、[Agent与证据](03-Agent与证据.md)。练习、闭卷题、面试表达统一放在这里，不再按模块重复出题。

使用临时 demo 和测试夹具，先查 `git status --short`，保留已有工作。下面的新指标是练习需求，不代表项目已实现；真实模型和外部服务不是离线学习必做项。

## 1. 做四项练习

### 跟一次请求，核对一次报告

跑默认经营复盘，生成数据并确认版本，启用人工复核。在浏览器 Network 记录预览、确认、建任务、详情、事件、审批与下载，只记认证字段名称，不保存值。

画 API/Worker 两条线，标注 202、waiting_review、重新排队、导出。刷新后解释历史事件来源；再驳回另一个任务，比较产物。

下载 report.json、report.md、evidence.json、research.json，选一条事实和一条解释：

1. 找 Claim 的 kind、evidence_ids、metrics。
2. 核对数据版本、商品、单位、周期与数值。
3. 文本研究对照 finding.support、quote 和逐项 review，默认复盘与高级研究分开看。
4. 看 evidence_selection 的来源选择和截断。
5. 单独判断推理支持、章节完整，不能只看引用存在。

再在高级库存 demo 手算 `20 × 30 / 324 ≈ 1.85 天`，不要混用不同路径的样例。

### 调试计算与错误引用

从根目录运行已有测试，单步可用 IDE pytest 或 pdb：

```bash
uv run pytest -q tests/test_commerce_review.py
uv run python -m pdb -m pytest -q tests/test_contracts.py::test_known_commerce_numbers_and_missing_period
uv run pytest -q tests/test_quality.py -k 'metric_tuple or wrong_product'
```

在 calculate_review、sales_summary、inventory_risks 返回前看周期、coverage、value、risk、fact_catalog。先预测缺一天、零净销量、过旧快照的结果，再对照断言。

参考 test_metric_tuple_rejects_entity_unit_period_snapshot_and_value，在个人测试中每次只改一个引用维度或构造未知 evidence_id，记录哪层拒绝。交付“字段 → 计算 → fact_catalog → Claim”映射及错误输入的独立预期，不放宽校验迁就错误对象。

用 [ScriptedCommerceModel](../../tests/fake_model.py) 画 messages → tool_calls → ToolMessage → 下一次请求，指出 Skill、委派和计量位置。这是“真实 SDK + 脚本协议替身”，不证明真实模型质量。

再画 Worker A/B 泳道，标出业务提交、检查点、文件写入/登记、租约失效。说明晚到结果在哪拒绝，哪些外部调用仍会重复。恢复测试含 SIGKILL 与子进程，只用临时测试数据。

### 新增一个可复算指标

在高级销售工具练习新增“本周期记账退款金额占支付金额比例”，建议键 refund_amount_pct、单位 percent。它不同于退款件数比例，也不是订单 cohort 退款率。

| 独立输入 | 预期 |
| --- | --- |
| 支付 10000 分、退款 400 分 | 4.00% |
| 支付为 0 | 不生成比例，说明分母不可用 |
| 退款大于同期支付 | 允许超过 100%，说明记账口径 |
| 缺记录 | 保留限制，不宣称完整周期 |
| 身份或商品/周期不匹配 | 沿用权限与完整绑定，不能误引用 |

顺序：service.sales_summary 的计算/labels/fact_catalog/definitions → deterministic_report 可选事实 → 复用绑定校验 → 独立小输入与报告断言 → 一条固定评估用例。缺键兼容并注意章节条数限制。

预期来自手算，不能用同一个函数生成。先专项再验证受影响报告；新增用例后记录新 dataset_size，历史结果不改写。默认复盘若也需要指标，应单独检查数据集计算与专用报告，不能假定旧工具改完自动生效。

每项练习只留一份记录：**目标/口径、入口、独立预期、观察、根因或改动、已验范围、未验项**。

## 2. 闭卷回答十二题

先独立作答，再展开要点；答不出来就回到源码。

| 题目 | 回查入口 |

| 2. 净销售额为何不是利润？缺行与零销量区别？ | calculate_review、sales_summary |
| 3. 202 后失败为何不矛盾？同键不同请求怎么办？ | start、create_task |
| 4. task_id、lease_token、checkpoint 各负责什么？ | claim、Worker、LeaseFencedSaver |

| 6. 人工复核怎样跨重启？next 为空就完成了吗？ | review、Worker.process |
| 7. multi 为何可能没委派？workflow 会调模型吗？ | collect、create_researcher |
| 8. Skill 为何不能代替授权？如何限制公开搜索词？ | RunContext、ToolGateway |

<details>
<summary>判定要点</summary>

1. 本人已确认的不可变版本，新导入不覆盖旧版本。
2. 未扣成本；缺记录是未知，零销量是明确观测。
3. 202 只确认登记；同用户同键不同哈希返回冲突。
4. 业务任务、本次执行身份、图进度。
5. 写前及写入期间保护租约；已发外部请求仍可能重复或收费。
6. 业务表保存决定、检查点保存中断，Worker 恢复；空 next 可能还有 pending writes。
7. 同时要求模型/web/公开词/非 workflow；workflow 仍可有结构化模型调用。
8. 指南不是强制授权；身份来自服务端，公开词逐字白名单。
9. Token 回执后计量，单次可能越阈值；未知回执阻止新调用。
10. 内容一致、来源存在、逐字对应，均不能独立证明推理成立。
11. 完整元组与程序渲染防错配；推理还需语义与人工核验。
12. 当前 App 游标轮询；结论受版本、样例、替身和环境限制。

## 3. 调试和验证只查这一处

| 现象 | 优先检查 |
| --- | --- |
| 页面能开，任务一直 queued | Worker、数据库是否一致、领取条件 |
| 401/403/422 | 会话、Origin/CSRF、Schema、数据版本归属和日期 |
| 工具有结果但报告缺内容 | manifest、截断、finding、Claim、章节 |
| runtime_budget / 模型超时 | 总截止时间、阶段耗时，区分总时限与读取超时 |
| degraded / 用量未知 | limitations、研究验证、回退标志、请求与回执 |

不要清零预算、吞异常或改成 succeeded 来掩盖故障。截图/HAR 只保留必要字段。

| 验证入口 | 可以证明 | 不能直接证明 |
| --- | --- | --- |
| 业务测试、固定 demo 评估 | 给定输入的行为与业务契约 | 真实模型质量 |
| SDK + 脚本模型 | 工具、Skill、委派与预算协议 | 真实研究能力 |
| 真实 PG 测试 | 测试库事务、锁与接管 | 生产库已恢复 |
| 真实模型 + 人工逐项核对 | 对应版本、数据和单次结果 | 稳定通过率、多 Agent 收益 |
| 浏览器、容器 CI、教学负载 | 对应环境和提交的交付链 | 目标 HTTPS、生产容量与验收 |

评估器保留 dataset_size、executed、passed，失败即停，不能把只执行一条写成全量通过。[compare_runs](../../evaluations/review.py) 要求同数据集/实现/模型预算、各策略至少三个不同完整轮次、绑定哈希的人工标签与成本；不能复制结果凑轮次。

命令统一查 [README](../../README.md#验证)、[评估文档](../04-evaluation.md)。无 TEST_POSTGRES_URL 时 PG 用例跳过；用临时 PG 或可丢弃服务，不指向个人运行库。浏览器测试可能改 docs/images 截图，运行后检查 diff。

备份要停所有写入者，保存业务库/检查点/运行文件/哈希清单，不含 .env 和数据库角色。恢复需可信备份、空目标库、新运行目录，别先 init。数据库与文件发布非原子，文件失败时数据库可能已提交，不能盲目重跑；命令统一看 [部署文档](../05-deployment.md)。

## 4. 怎样准确介绍项目

一分钟参考：项目面向电商经营复盘，先确认数据版本，由程序计算指标和变化贡献，模型在受控范围内提出候选解释与核对建议。FastAPI 负责认证和任务登记，Worker 通过数据库队列及租约执行，LangGraph 管流程、检查点和人工复核；高级竞品研究才按条件使用 Deep Agents。报告保存指标与原文依据，可追溯、取消、恢复和下载。

用十二题展开工程取舍，尤其说明业务写与检查点都要保护、幂等提交不等于外部调用恰好一次、引用齐全不等于推理正确。可以衔接 Java 的事务、权限、幂等与恢复责任，但本项目实现是 Python/FastAPI。

说“我实现/验证了”前，准备自己的改动、断言和复现证据。来源见 [PROVENANCE](../../PROVENANCE.md)，继承代码和 AI 辅助不写成从零原创，教学数据不写成真实业务规模。验证结论按版本/环境查原记录，分别报告 PASS、FAIL、BLOCKED/UNTESTED。
