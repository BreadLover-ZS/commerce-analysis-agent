## 先跑一条当前主线

按 [README](../../README.md#五分钟本地启动) 启动本地 demo，使用 `demo@example.com / demo-commerce-2026` 登录。

1. 在默认的“经营复盘（固定流程）”生成模拟数据，或导入符合模板的 CSV。
2. 查看预览，点击“确认使用此数据版本”，检查周期和数据质量。
3. 勾选草稿复核，开始分析；查看任务状态和“依据”。
4. 批准后下载报告与证据；刷新页面，观察任务和历史事件重新加载。

程序计算事实与变化观察；live 模型只选择证据允许的候选假设并提出核对建议。demo 不调用真实模型或搜索。数据是否模拟与执行方式 demo/live 是两回事，模拟数据也可以用于真实模型测试。

第一轮只走固定流程。库存与竞品研究在“库存与竞品研究（高级）”，读第 3 篇时再进入；历史 `examples/` 留作上游对照。

## 项目地图

```text
React 工作台 → FastAPI → 数据库任务表 ← Worker
                                      ↓
                          LangGraph：计划到交付
                                      ↓
                  确定性经营工具 / 受限研究 Agent
                                      ↓
                      证据 → 校验 → 复核 → 导出
```

- `app/api/` 接收请求、认证；`app/storage/` 保存任务、租约、预算和证据。
- `app/commerce/` 导入数据、计算指标；`app/tasks/` 执行、续租、取消和恢复。
- `app/research/` 组织流程、Agent 和报告；`frontend/src/` 展示进度、依据与诊断。
- `tests/` 检查行为；`evaluations/` 检查固定业务用例。任务表是队列，检查点保存图进度，当前没有 RabbitMQ。

## 怎样安排时间

每次用 60～90 分钟读一段调用链、做一次观察，再关掉源码复述。六周安排只是一种节奏：

| 周次 | 阅读与行动 |
| --- | --- |
| 1 | 总览 + 后端主链前半：启动、数据版本、指标口径 |
| 2 | 后端主链后半：认证、幂等、Worker、故障接管 |
| 3 | Agent与证据前半：LangGraph、人工中断、三种策略 |
| 4 | Agent与证据后半：工具边界、预算、证据与报告校验 |
| 5 | 实践与自测：核对产物、调试、增加一个受控指标 |
| 6 | 复述主链和失败恢复，按需继续部署与真实服务验证 |

每段笔记只记六项：**业务问题 → 入口/调用者 → 输入输出 → 持久化 → 失败恢复 → 验证依据**。先定位表格里的函数，不必从头通读长文件。
