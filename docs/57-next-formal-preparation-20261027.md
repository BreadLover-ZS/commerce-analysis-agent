## 为什么当前不能启动正式轮

1. `evaluations/diagnosis.py` 的旧正式执行循环使用 `critical_failure()`；普通必答项或完成度失败未必停止。其冻结计划只支持整轮参数，缺少逐 Task 人工审查后才推进的门禁。
2. `diagnosis_plan.reconcile_history()` 及正式预算入口期望普通正式 `run.json` 链，当前最新叶子是八次小批形成的探针链。不能拿旧 PASS 父节点、伪造普通 run.json 或将 UNKNOWN 清零来绕过。
3. `diagnosis_probe.validate_selection()` 刻意只允许已执行旧输入。为了运行新正式题包去放宽它，会破坏防止用正式题做调试的边界。
4. 旧 UNKNOWN 的严格对账仍缺直接绑定证据。先前用户批准的保守冻结限定于新探针，不能自动扩成新正式轮授权。后续若明确批准正式保守承接，应仍保留 UNKNOWN 与严格 BLOCKED，单独验证冻结的来源和额度；不能伪造对账证书。

因此本轮 manifest 为 `PREPARED_LOCAL_ONLY_PAID_ADMISSION_BLOCKED`。实际调用两个现有入口验证：旧正式入口因准备状态拒绝，探针入口因新输入不属于历史绑定题源拒绝；两者都没有到达凭据或请求边界。这是有效的本地安全检查，不是新正式执行入口已实现的证明。
