## H01 失败与修复

根因是新增探针 HTTP 上限为 2，但 Task/提示词仍显示 12 次模型额度；同时退款工具的能力表遗漏其实际已返回的支付金额。模型选用“排名＋另查支付金额”，还需第三次退款查询。评分 FAIL 有效，不能删除范围金额义务。

修复为：冻结 Task 与 HTTP 额度一致；显式冻结决策保留额度 0 并保持旧 Task 缺省逻辑；准确声明退款工具的合并输出；读密钥前验证结构最低调用数。预算提示、图执行和 HTTP 守卫使用一致的边界。

免费回放中，原顺序仍 FAIL，高效顺序严格 PASS；模型／决策额度都显示 2 → 1。实际复测选择排名＋退款分析，两次成功调用，无额外纠错或补发。完整问题、反例、金额及源码记录见 [55 号根因修复报告](55-H01-probe-budget-root-cause-and-repair-20261026.md)。
