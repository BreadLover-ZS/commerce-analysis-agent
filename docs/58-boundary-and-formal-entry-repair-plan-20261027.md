# 57号阻断修复与本地验收方案

用户确认全部修复并完成本地闭环：修复边界同义判别，补正式入口逐Task审查、首错停止和探针预算承接；旧版本兼容、独立反例及集成验证通过后，重新冻结未执行U题包。真实模型请求0、不增加额度，G7排除。旧UNKNOWN和历史失败/账本不改，不提交推送。

## 根因与版本边界

生产answer-contract-v4与独立v3评分的词面边界识别漏掉“不适用的边界”，二者共同为false并不证明正确。不能只改正式题面。新增answer-contract-v5及独立评分v4，以作者声明的同义表达、否定表达、数值义务和真实来源适用性为反例；旧v4/v3按旧任务恢复。

为避免把已存v16/固定v6任务重解释为新语义，冻结服务端边界策略版本到新Task；缺省字段的旧任务继续旧语义。图与计量协议保持v16/固定v6/发送v2，新的子契约版本必须出现在任务/报告和正式包schema5中。新字段的幂等重试也必须复用原冻结值。

当前旧正式CLI只调用critical_failure，不满足普通完成度失败立即停；也无法承接probe.json父链。保留旧正式入口及旧探针“只能使用旧输入”保护，新增正式单Task入口，共享现有一次任务执行、SDK、RequestBudget和账本审计，不复制一套模型实现。

## 正式入口约束

1. 读密钥前验证完整20题/96位的新包、源码/子契约、正确下一位、最新父回执及审查、历史费用和冻结、剩余预算；当前真实发送授权保持关闭。
2. 每次仅一Task，Task额度与该位HTTP上限一致，决策保留0、首错策略冻结、SDK重试0。HTTP发送前再次检查源码和累计硬额度。
3. 协议、模型、工具、报告校验、任何自动评分失败、UNKNOWN或预算不足立即停止；未获绑定回执hash的逐份PASS审查，不得开始下一位。
4. 排他预算承接，费用始终累计；新增UNKNOWN不得自动冻结承接。已保存响应不能为补checkpoint重复收费。失败后源码修复不拼接旧源码质量成绩。
5. 正式保守承接必须明确绑定新计划、2000万上限、原UNKNOWN持有和用户授权范围；不从探针授权自动推导。单独读取原始证据，不能伪造严格对账证书。

## 验收顺序

- 先独立红例：同义/否定、旧契约恢复；非关键自动失败、审查FAIL/PENDING/错hash、新UNKNOWN、重复claim、旧冻结清零、错位/改包/源码/模型等凭据前阻断。
- 新语义Worker和固定流程用独立开发数据及已使用旧输入运行，不能把U或旧未执行T14—T20当作开发回放。模型交互均真实SDK的MockTransport，网络禁止。
- 正向正式入口用模拟题包/模拟账本完成至少相邻两Task、逐份审查和费用审计；负向首次坏响应不能发送第二条，SDK异常与恢复材料保留。
- 专项通过后运行完整隔离PostgreSQL回归、必要Chrome回归、缺陷变异、旧267份评分及历史字节保护；新题包仅元数据预检，保持UNEXECUTED。
- 最终冻结匹配新源码的schema5题包和未授权启动材料，给出本地PASS、真实模型UNTESTED、预算/授权边界。只有本地证据可支持的结论才标PASS。

实施方向准备度95%：已核对重复入口、旧契约路由、SDK零重试和HTTPX异步发送前钩子；复用锁定依赖和既有Worker，无新增依赖。此分数不是模型成功率或无bug保证。参考：[SDK重试](https://github.com/openai/openai-python#retries)、[HTTPX事件钩子](https://www.python-httpx.org/advanced/event-hooks/)。
