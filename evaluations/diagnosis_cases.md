# 诊断问题集 v1

60 条唯一 caseId，开发/回归/保留集各 20 条。`diagnosis_cases.json` 保留原始销售记录、
授权范围、两期、可选库存/规则、独立预期、必要工具集合、停止/故障条件和基线能力分组。
这是问题与事实契约；还没有完成 G6 Agent 评分和真实模型运行。

预期金额固化在 JSON 中，由独立原始记录参考实现复核；不调用生产指标内核生成答案。
只有文档双 SKU 样本属于手算基准，其他样本属于第二实现复核，不能全部称为人工标注。
已有测试仅对开发/回归数据检查指标；保留集只做结构、输入唯一性与预期一致性检查，
不用于 Prompt 调试或挑选最佳结果。

`business_input()` 显式排除 caseId、split、facet、expected 和 harness。
运行器只能把其中的业务材料写入版本化数据包，通过正常 Task API 运行；
不能把原始 case 对象、预期轨迹或场景标签拼接到模型上下文。
商品名称保持普通业务名称；专门的注入样本明确保留攻击文本，但不会由其扩大工具权限。

共同能力与新增能力分开比较；不同的合理路径均可接受，required_tools 是必要证据类别而非唯一顺序。
`execution=admission/fault` 是代码/恢复门禁，不能把它们的脚本通过率冒充真实模型效果。
保留集包含 20 个可受理的业务任务，若某个任务由程序准入/缺数门禁提前结束，须单列真实模型未执行，
不能把零次请求算成一次真实模型回答。

`diagnosis_targets_v1.json` 记录硬门禁、90% 目标及测量边界。
真实延迟/成本目标暂为空，等待明确提供方、模型、付费预算和基线测量；不以本地毫秒数推出线上 SLA。
G4/G5/G6 仍须实现库存/规则导入、请求/故障 fixture 和独立报告审查器，才能运行完整问题集。
